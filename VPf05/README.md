# Генератор статей с помощью цепочки запросов

Данный проект представляет собой приложение, которое генерирует полноценную статью в формате Markdown на основе заданной темы. Генерация выполняется через **цепочку запросов** (chain) с использованием LangChain и OpenAI (или совместимого API через прокси).

## Структура проекта
project_root/
├── .env.example # Пример переменных окружения
├── .env # Файл с вашими переменными (создаётся пользователем)
├── requirements.txt # Зависимости
├── README.md # Этот файл
├── main.py # Основное приложение (меню для выбора кейсов)

├── src/ # Исходный код

## Установка

1. Клонируйте репозиторий или скопируйте файлы в нужную директорию.
2. Создайте виртуальное окружение (рекомендуется):
   ```bash
   python -m venv venv
   source venv/bin/activate  # Linux/Mac
   venv\Scripts\activate     # Windows
Установите зависимости:

bash
pip install -r requirements.txt
Настройка (обязательно!)
Важно! Если вы находитесь в стране, где OpenAI API недоступен (например, Россия), вы обязаны использовать прокси-сервер. Без этого вы получите ошибку 403 Forbidden с сообщением unsupported_country_region_territory.

Скопируйте .env.example в .env:

bash
cp .env.example .env
Отредактируйте .env и укажите свои данные:

Переменная	Описание
OPENAI_API_KEY	Ваш API-ключ (обязательно).
OPENAI_BASE_URL	URL прокси-сервера (например, https://openai.api.proxyapi.ru/v1). Если не указан, используется стандартный https://api.openai.com/v1.
OPENAI_MODEL	Модель (по умолчанию openai/gpt-4o-mini).
TEMPERATURE	Температура для цепочки (по умолчанию 0.3).
LOG_LEVEL	Уровень логирования (DEBUG, INFO, WARNING, ERROR).
Пример .env для пользователей из России:

env
OPENAI_API_KEY=sk-ваш_ключ_от_прокси
OPENAI_BASE_URL=https://openai.api.proxyapi.ru/v1
OPENAI_MODEL=openai/gpt-4o-mini
TEMPERATURE=0.3
LOG_LEVEL=INFO
Если вы не укажете OPENAI_BASE_URL, программа попытается обратиться к официальному API OpenAI, что приведёт к ошибке доступа. В логах вы увидите предупреждение:

text
⚠️  Переменная OPENAI_BASE_URL не задана! Будет использован стандартный URL OpenAI.
Использование
Основной режим (работа с промптами)
Запустите main.py:

bash
python main.py
Программа:

Загрузит все JSON-промпты из папки prompts/ (если они есть).

Если папка prompts пуста или отсутствует, автоматически перейдёт в режим цепочки (генерация статьи).

При наличии промптов выведет список доступных кейсов и предложит выбрать номер.

После выбора кейса попросит ввести текст задачи.

Можно указать температуру и включить потоковый вывод.

Ответ будет выведен в консоль и (опционально) сохранён в файл.

Режим цепочки (генерация статьи)
Если вы выбрали в меню пункт [Спец. режим] Генерация статьи через цепочку (chain) (или если папка prompts пуста), программа запросит тему статьи и выполнит последовательность шагов:

Анализ темы – выделение ключевых аспектов, аудитории, стиля.

Подбор источников и инструментов – рекомендация внешних данных и API.

Создание плана – структура статьи (заголовки, подзаголовки).

Написание статьи – генерация полного Markdown-текста.

Ревью и корректировка – финальная правка.

Готовая статья сохраняется в папку output/ с именем article_<slug>.md.

Самостоятельный запуск цепочки
Цепочку можно запустить и напрямую, без main.py:

bash
python src/chain.py "Тема статьи" --out-dir ./output
При этом также требуется корректно настроенный .env с OPENAI_BASE_URL.

Пример
bash
python main.py
Если папка prompts пуста, сразу запросит тему. Введите, например:

text
есть ли жизнь на марсе
После завершения в папке output/ появится файл article_est_li_zhizn_na_marse.md с готовой статьёй.

Тестирование
Для запуска юнит-тестов выполните:

bash
pytest tests/
Тесты проверяют вспомогательные функции parse_json_spec и slugify, используемые в цепочке.

Дополнительные возможности
Потоковый вывод – при работе с обычными промптами можно включить пошаговую печать ответа.

Сохранение результата – после получения ответа можно сохранить его в текстовый файл.

Гибкая настройка – все параметры модели и прокси управляются через .env.

## Проблемы с SSL-сертификатами при установке

Если при выполнении `pip install -r requirements.txt` возникает ошибка `SSL: CERTIFICATE_VERIFY_FAILED`, это означает, что ваш антивирус, корпоративный прокси или сетевое оборудование подменяют HTTPS-сертификаты. Для обхода можно использовать один из способов:

1. Указать доверенный сертификат через переменную `PIP_CERT`.
2. Временно игнорировать проверку хоста:
   ```bash
   pip install --trusted-host pypi.org --trusted-host files.pythonhosted.org -r requirements.txt
Использовать HTTP-зеркало без SSL:

bash
pip install -i http://pypi.douban.com/simple/ --trusted-host pypi.douban.com -r requirements.txt
Настроить прокси для pip (если требуется):

bash
pip install --proxy http://proxy-server:port -r requirements.txt
После установки пакетов проверьте их наличие командой pip list и запускайте проект.

Ошибка 403 Forbidden
Если вы получили ошибку:

text
Error code: 403 - {'error': {'code': 'unsupported_country_region_territory', ...}}
– значит, вы не указали OPENAI_BASE_URL в .env.
Проверьте, что переменная задана и указывает на рабочий прокси-сервер.

Ошибка «Invalid format specifier in f-string template»
Если вы видите:

text
ValueError: Invalid format specifier in f-string template. Nested replacement fields are not allowed.
– это означает, что в одном из шаблонов промпта присутствуют фигурные скобки, которые LangChain пытается интерпретировать как переменные. В текущей версии chain.py эта ошибка уже исправлена (фигурные скобки в системном сообщении экранированы). Если вы используете старую версию, обновите файл chain.py до актуальной.

Другие ошибки

Убедитесь, что ключ OPENAI_API_KEY корректен.

Проверьте доступность прокси-сервера (например, через браузер или curl).

Если используете GenAPI, укажите GENAPI_URL (но приоритет у OPENAI_BASE_URL).
