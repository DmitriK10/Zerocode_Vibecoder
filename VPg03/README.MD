# 🐾 Агент по фактам о животных (LangChain + LangGraph)

Этот проект демонстрирует создание **интеллектуального агента** на базе LangChain и LangGraph, который умеет отвечать на вопросы пользователей о породах кошек и собак, используя встроенные инструменты (функции). Агент имеет долгосрочную память (SQLite) и возвращает структурированные ответы в формате JSON.

Проект создан в рамках изучения фреймворков для LLM-приложений и показывает, как можно использовать **LangChain** для быстрого прототипирования агентов с инструментами.

---

## 🧠 Что умеет агент?

- **Отвечать на вопросы** о породах кошек и собак.
- **Использовать инструменты** (`get_cat_fact`, `get_dog_fact`) для получения фактов.
- **Помнить контекст диалога** между запросами (благодаря `SqliteSaver`).
- **Возвращать ответы в формате JSON** с полем `facts` (список фактов).
- **Работать через прокси** (например, proxyapi.ru) и ограниченной моделью GPT-3.5.

---

## 📦 Требования

- Python 3.10+
- API-ключ к OpenAI (или прокси-сервису, например, proxyapi.ru)
- Установленные зависимости (см. `requirements.txt`)

⚙️ Как это работает
Загрузка окружения – переменные из .env загружаются через python-dotenv.

Создание модели – ChatOpenAI с параметрами из окружения (прокси, модель, температура).

Определение инструментов – две функции-инструмента (get_cat_fact, get_dog_fact), которые агент может вызывать.

Создание агента – используется create_react_agent из langgraph.prebuilt с системным промптом и памятью.

Память – SqliteSaver сохраняет состояние диалога в SQLite, что позволяет агенту «помнить» предыдущие запросы.

Парсинг ответа – извлечение JSON из ответа модели (поддерживаются маркдаун-блоки и обычный JSON).

Запуск – тестовые запросы для трёх пользователей демонстрируют работу агента.

🔧 Используемые технологии
LangChain – для управления LLM и цепочками.

LangGraph – для создания реактивных агентов с состоянием.

OpenAI SDK – через langchain-openai для вызова моделей.

SQLite – для долгосрочного хранения состояния диалога.

python-dotenv – для управления переменными окружения.

📌 Особенности реализации
SRP и DIP – код разбит на отдельные функции с чёткими обязанностями; зависимости передаются через параметры.

Обработка ошибок – любые исключения при вызове агента перехватываются и возвращаются в виде сообщения.

Нормализация ввода – породы приводятся к нижнему регистру и очищаются от пробелов.

Гибкий парсинг – поддерживает JSON в маркдаун-блоках и обычный текст.

Долгосрочная память – состояние сохраняется между запусками в SQLite.
