# Генератор отчётов в Google Sheets

Приложение на Python с графическим интерфейсом (tkinter) для автоматической генерации структурированных отчётов и записи их в Google Таблицы. Использует сервисный аккаунт Google Cloud для аутентификации.

## Возможности

- Удобный GUI для ввода параметров отчёта:
  - Период (дата начала и окончания)
  - Тип отчёта (Ежемесячный, Квартальный, Годовой, Произвольный)
  - Отдел (Продажи, Маркетинг, Разработка, Администрация, Финансы)
  - Ответственное лицо
  - Комментарий
- Автоматическая генерация случайных данных с реалистичными метриками:
  - **Основные метрики**: выручка, количество клиентов, конверсия, средний чек, количество сделок, возвраты, новые клиенты, повторные покупки.
  - **Детализация по дням**: дата, выручка, клиенты, сделки.
- Профессиональное форматирование создаваемого отчёта в Google Sheets:
  - Объединение ячеек для заголовков
  - Цветовые выделения (заголовки, метаданные, итоги)
  - Настройка ширины столбцов
- Модульная архитектура с соблюдением принципов SOLID (SRP, DIP).
- Покрытие ключевых модулей тестами (pytest + mocks).

## Требования

- Python 3.8+
- Аккаунт Google Cloud с включённым **Google Sheets API**
- Сервисный аккаунт с правами редактора для целевой таблицы
- Доступ в интернет для взаимодействия с Google API

1. **Клонируйте репозиторий** (или скопируйте файлы в рабочую директорию).

2. **Создайте и активируйте виртуальное окружение**:
   ```bash
   python -m venv venv --upgrade-deps
   source venv/bin/activate      # Linux / macOS
   venv\Scripts\activate         # Windows

bash

Настройте Google Cloud:

Перейдите в Google Cloud Console.

Создайте новый проект (например, «Excel Factory»).

В разделе APIs & Services → Library включите Google Sheets API.

Перейдите в APIs & Services → Credentials.

Создайте сервисный аккаунт (Service Account) с ролью Owner или Editor.

Создайте ключ для этого аккаунта в формате JSON и скачайте файл.

Переместите скачанный JSON-файл в корневую папку проекта.

Предоставьте доступ сервисному аккаунту к вашей Google Таблице:

Откройте нужную Google Таблицу.

Нажмите «Поделиться» и добавьте email сервисного аккаунта (он указан в JSON-файле как client_email).

Назначьте роль Редактор.

Настройте переменные окружения:

Создайте в корне проекта файл .env (скопируйте из примера ниже).

Укажите абсолютный путь к JSON-ключу и идентификатор таблицы (ID берётся из URL таблицы: https://docs.google.com/spreadsheets/d/<ID>/edit).

Пример содержимого .env:

Использование
Запустите приложение:

bash
python report_generator.py
В открывшемся окне заполните поля:

Дата начала и Дата окончания (формат YYYY-MM-DD).

Тип отчёта – выберите из выпадающего списка.

Отдел – выберите из списка.

Ответственное лицо – введите ФИО.

Комментарий – необязательное поле (если оставить пустым, в отчёте будет указано «(не указан)»).

Дождитесь сообщения об успехе – в вашей Google Таблице появится новый лист с именем, содержащим тип отчёта и период. Данные будут записаны с полным форматированием.

Принципы SOLID
Single Responsibility Principle:

CredentialsProvider отвечает только за загрузку учётных данных.

SheetsClient отвечает только за взаимодействие с API Google Sheets.

ReportGeneratorApp отвечает только за GUI и формирование отчёта.

Dependency Inversion Principle:

SheetsClient зависит от абстракции CredentialsProvider (передаётся через конструктор), что позволяет легко подменять провайдер для тестирования.

Тестирование
Модульные тесты написаны с использованием pytest и pytest-mock. Они покрывают основные методы класса SheetsClient и CredentialsProvider, не выполняя реальных запросов к Google API.

Запуск тестов:

bash
pytest tests/
Все тесты должны успешно проходить (10 тестов).

Примечания
При первом запуске может потребоваться подтверждение доступа через браузер, но при использовании сервисного аккаунта этого не требуется.

Если вы используете прокси, настройте переменные окружения HTTP_PROXY и HTTPS_PROXY.

В случае ошибок 403 (недостаточно прав) проверьте, что сервисный аккаунт добавлен в редакторы таблицы.

Имена листов в Google Sheets ограничены 100 символами – при слишком длинном названии отчёта оно будет обрезано.
