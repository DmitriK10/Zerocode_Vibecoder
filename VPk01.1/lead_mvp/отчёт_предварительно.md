# Отчёт по практике – Lead Intake MVP

Проект решает задачу автоматизации приёма заявок (лидов) для малого бизнеса, онлайн-школ и сервисных компаний. Заявки, приходящие через веб-формы, мессенджеры или соцсети, 
автоматически сохраняются в структурированную базу данных SQLite, а менеджер получает мгновенное уведомление в лог-файл. Это исключает потерю клиентов, ускоряет реакцию 
на запросы и даёт возможность анализировать входящий поток.
## 2. Входные данные

POST /lead принимает JSON-объект со следующими полями:
- `name` (string, обязательное) – имя клиента.
- `contact` (string, обязательное) – телефон или email.
- `source` (string, обязательное) – источник заявки (landing, facebook, telegram и т.д.).
- `comment` (string, опциональное) – комментарий клиента.

Пример валидного запроса:
```json
{
  "name": "Ирина",
  "contact": "+79990000000",
  "source": "landing",
  "comment": "Хочу консультацию по тарифам"
}
3. Выход / результат
Бизнес получает:

Надёжное сохранение каждой заявки в SQLite (таблица leads с полями id, created_at, name, contact, source, comment).

Уведомление о новой заявке в файл events.log в формате: [timestamp] New lead saved: id=<id>, contact=<contact>.

HTTP-ответы: 201 Created с {"id": <id>, "message": "Lead saved successfully"} при успехе, 400 Bad Request при ошибках валидации, 500 Internal Server Error при проблемах с БД или логом.

Возможность легко расширить уведомления (email, Telegram) без изменения основной логики.

4. Как запустить
Проект запускается за 5–10 минут. Подробная инструкция находится в README.md репозитория.

Ссылка на README:
https://github.com/username/lead_mvp#readme

Кратко:

Клонировать репозиторий, перейти в папку lead_mvp.

Создать виртуальное окружение: python -m venv venv.

Активировать окружение: source venv/bin/activate (Linux/macOS) или venv\Scripts\activate (Windows).

Установить зависимости: pip install -r requirements.txt.

Запустить сервер: uvicorn app.main:app --reload.

Отправить тестовый запрос через curl или Postman на http://127.0.0.1:8000/lead.

6. Ошибки и как решал(а)
SSL-ошибка при установке пакетов (корпоративный антивирус блокирует PyPI).
Решение: использовал pip install --trusted-host pypi.org --trusted-host files.pythonhosted.org -r requirements.txt.

FastAPI возвращал 422 вместо 400 при отсутствии обязательного поля contact.
Решение: добавил кастомный обработчик RequestValidationError, который преобразует 422 → 400 с понятным сообщением.

Проблема с кириллицей в консоли при выводе данных из БД (Windows).
Решение: не влияет на работу приложения; данные в БД и логе сохраняются корректно (UTF-8). Для просмотра в консоли использовал chcp 65001.

Изначально код использовал устаревший @validator из Pydantic v1, а в requirements.txt был Pydantic v2.
Решение: заменил на @field_validator и model_dump() вместо .dict(), привёл код к совместимости с Pydantic v2.
